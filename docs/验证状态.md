# v0.3.1 本地实现验证

本版本已经实现本地测试版插件，验证结果保存在 [validation.json](validation.json)，性能测量保存在 [benchmark.json](benchmark.json)。

## 本轮结果

- 101 个 Python 自动化用例通过，没有跳过用例；另有 Node.js 前端模型断言。
- Python 3.14.4、Windows 11；标准测试无需额外依赖。
- 与 AstrBot v4.29.4 原始 FunctionTool、ToolSet 和权限代理完成构造、拒绝分支、会话查找及历史查询契约验证。
- 上游源码先核对 Git blob SHA，再提取原始类；宿主生命周期、工具执行器和适配器仍使用合成替身，不是完整生产实例联调。
- 测试生成的 SQLite 数据库仅位于测试临时目录，完成后清理；没有使用真实聊天记录或外部模型。

## 覆盖的行为

| 权限 | 默认关闭、群聊入口拒绝、跨平台同号、机器人绑定不符、伪称管理员、逐用户会话授权、输出前撤权 |
| 引用 | 随机引用绑定当前用户/实例/私聊，类型和有效期校验，容量限制，篡改或过期拒绝 |

| 工具准入 | 真实执行器实例与类型检查，权限代理保留，读取后拒绝其他工具，读取前不更改工具对象，新轮次与卸载边界 |
| 只读 SQL | 写入/索引/附加数据库等拒绝，数据文件读取前后哈希一致，参数字面匹配，不同平台及群隔离会话归属 |
| 历史与游标 | 新消息和删除锚点下续查、变化指纹拒绝、多个私聊旧对话、系统/工具内部记录排除、上下文来源校验 |
| 用户体验 | 名称歧义等待下一轮，范围缺失先问，日期未知先询问，禁止同轮扩大范围，空历史与访问失败区分 |
| 资源 | 扫描未命中也计入预算，多会话公平分配，长正文裁剪保留记录引用，工作进程复用、启动取消和空闲退出 |
| 审计 | 只含查询者、来源、状态等元信息，不包含聊天正文或关键词 |
| 管理 API | 宿主登录用户与插件命名空间、输入限制、修订冲突、同时保存、失败恢复、未知实例拒绝、仅读取平台元信息 |
| 配置生效 | 四个管理 API 与三个 LLM 工具分离、宿主保存接口调用、关闭旧查询服务并恢复未锁定轮次 |
| 前端模型 | 文本转义、会话标识构造、重复条目、资源边界、独立草稿与原型污染路径拒绝 |
| 私聊名称 | 配置名称优先、昵称查询失败/超时回退、账号响应不符拒绝、跨平台/机器人缓存隔离、过期刷新、无权限不补查、搜索及上下文一致 |
| 查询表达 | 额度和未读总数分开、正文包含日期仍标记未知时间、名称筛选和格式化 |
| 多会话查询 | 双目标批量定位与续查保存完整范围、私聊日期不再阻塞、拒绝撤权/续查改条件及歧义自动选择 |
| 私聊目录 | 数据库端授权过滤、空授权不读库、跨平台同号隔离、稳定分页及插入删除、游标归属与撤权复核、只返回元信息 |
| 最近记录 | 对话尾部倒序、优先最近更新的旧对话、每私聊每轮 50 条上限、同轮重复调用不重置、下一轮向前续查、多个来源共享总预算、活动对话改变时失效 |
| 自定义回看条数 | 缺项默认 50、整数边界校验、管理页保存往返、服务重新创建后读取新值、10/75 条实际扫描、不能突破全轮总额度、补读共同计数、群查询不受私聊小额度限制 |

## 独立视图交互验证

本轮通过本地浏览器操作 `tools/preview_view.py`，仅使用内存配置及合成号码／群名，未连接用户服务器或真实 NapCat。已验证新增群与私聊、账号识别、别名编辑、保存后状态更新、越界值阻止保存、放弃草稿确认、两页面保存冲突后保留草稿、全部私聊授权提示及 HTML 群名转义。桌面、手机和深色布局另做视觉检查。

预览复用真实 `ConfigEditor`，但桥接和登录上下文由预览服务模拟；真实宿主 iframe、原配置页并发保存、插件热重载及页面关闭行为仍需完整环境验收。

## 性能观察

合成库约 11.9 MiB，包含 3000 条中文群消息。单个独立工作进程：

- 冷启动与元信息查询约 0.166 秒。
- 20 次 IPC 分页、累计扫描 500 条约 0.554 秒。
- 工作进程只启动 1 次，峰值工作集约 26.5 MiB。
- 查询进程不导入 AstrBot；普通聊天不会启动工作进程。

此测量只包含本机的查询工作进程，不包含 AstrBot/NapCat、模型、真实网络和生产并发。它不是 2 核 2 GB Linux 服务器的压测保证，也不是所有数据分布下的上界。

## 仍需真实/完整环境验证

1. 完整 AstrBot 启动、独立管理视图发现及桥接、登录保护、原配置页交互、加载/热重载/卸载，以及其他插件组合。
2. 内部 runner 注册表与执行器在目标部署版本中的实际生命周期；遇到不匹配只关闭历史查询。
3. 实际 NapCat 返回格式、断线行为、机器人账号切换和成员状态更新延迟。
4. POSIX 工作进程地址空间上限及宿主文件权限；Windows 目前只有体积限制与测量，没有等价内存硬限制。
5. 群成员状态与数据库读取不能组成原子事务；前后检查仍存在最后校验后的时间差。
6. 稳定游标不等于正文版本快照；删除的旧消息无法恢复，数据库恢复/ID 复用仍需保守失效处理。
7. 未经过受控执行器的插件内部代码、独立任务和其他会话不属于本层拦截保证。
8. 真实模型能否稳定按说明选择会话、等待澄清、正确归纳和引用来源。本轮没有拿真实消息调用模型。
9. 对超大来源目录、缺失历史时间和高频多来源请求，可能需要缩小范围或多轮续查；不能声称搜索覆盖了全部历史。

## 复现

标准用例：

```powershell
python -m unittest discover -s tests -t . -v
node tests/test_view_model.mjs
python tests/benchmark.py
```

生成验证摘要并检查上游类契约：

```powershell
python tools/validate.py --upstream-source PATH_TO_ASTRBOT_V4_29_4_SOURCE
```

该可选检查需要 requirements-dev.txt 中的测试依赖。上游来源必须为已核验版本，脚本会检查源码哈希。

历史研究的第一轮 22 项、第二轮 28 项观察仍保留在外层 feasibility 目录中，不能与本版本 101 个自动化用例混为同一测试计数。性能段沿用 v0.1.0 的查询工作进程基准；本轮未重复进行查询性能测量。没有向外部模型发送真实或合成聊天内容；自然语言回答的遵循程度仍取决于模型。

v0.3.1 本地合成页面验证了将回看条数改为 75 后保存、刷新仍为 75，以及非整数 1.5 无法保存。该操作没有连接生产数据。
