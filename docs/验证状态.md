# 验证状态

已有两轮本地可行性实验，均使用合成数据。本文为状态摘要，不代替完整探针或生产环境验收。

实验环境：Windows 11、Python 3.14.4、SQLite 3.50.4。源码基线为 AstrBot v4.29.4，提交 `61335414433db721b3f7ecc93f90deafe0a59d78`。

第一轮记录 22 项观察，第二轮记录 28 项观察；这些数字包含失败对照、条件成立和未解决限制，不是“全部功能测试通过”的数量。

| 范围 | 已有证据 | 剩余限制 |
| --- | --- | --- |
| 工具准入 | 上游原始分派/执行方法配合实验准入层，能在读取前保留普通调用，读取后拒绝新工具；既有后台任务能完成 | 需要版本相关内部接入；完整宿主、插件重载和独立 Agent 路径未验证 |
| 只读访问 | 合成数据库的写入、建表、建索引、附加数据库等被拒绝，纯读取期间数据和结构哈希未改变 | 尚未接入正式权限配置和宿主环境 |
| 超时退出 | 可协作 SQLite 查询能在约 5 秒中断；隔离进程能在期限后回收 | 不可协作线程不能被安全强杀；有调度和清理开销，内存及队列策略需补测 |
| 稳定游标 | 新消息和删除已读锚点不再造成页码漂移；来源和调用者绑定可校验 | 不恢复已删除记录，不保存永久正文快照；恢复数据库、ID 重用等需失效策略 |
| 群资格 | 合成的退群、未知、接口异常及撤权场景拒绝正文，读中资格变化时丢弃结果 | 未调用真实 NapCat；成员状态与 SQLite 不能形成原子事务 |
| 公平额度 | 两个长会话各分配 250 条；短会话 20 条后可将剩余 480 条给另一会话 | 整轮累计排队 5 秒是后续新增规则，需实现并专项验证 |

最新确认的边界：允许经过验证的内部接入；检查失败仅停用历史查询。拦截只保证本轮经过受控入口的新 LLM 工具调用，不进行宿主级管控，不声称阻止其他插件任意内部代码。

外层本地工作区仍保留 `feasibility/README.md`、`feasibility/ROUND2.md`、对应结果 JSON 和源码快照。为了保持独立仓库轻量，初始化阶段未将这些实验材料和依赖环境复制入库；因此本仓库暂不包含完整实验的复现脚本。
