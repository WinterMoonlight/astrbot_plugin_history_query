# 开发与当前实现

## 当前状态

v0.1.0 已从骨架进入本地测试版。实现了 AstrBot 入口、配置、三个 LLM 工具、逐用户权限、当前群访问校验、预算队列、只读数据库工作进程、稳定游标和上下文引用。

常规运行使用 Python 标准库以及宿主已经提供的 AstrBot API，不增加额外运行依赖。默认关闭功能，空配置无查询权限。

## 模块

| 文件 | 职责 |
| --- | --- |
| main.py | 工具注册、宿主 hook、版本判断、按事件绑定执行器及卸载 |
| config.py / state.py | 严格配置解析、可信事件身份、逐用户授权、受限引用与本轮状态 |
| gate.py | 已验证内部接口的接入；不替换原工具对象，保留宿主权限代理 |
| scheduler.py | 单执行槽位、有限队列、独立累计排队/执行预算 |
| process.py / worker_entry.py | 按需复用和空闲回收独立 Python 进程，超时终止 |
| database.py | 固定只读 SQL、群隔离会话归并、两种正文格式、体积限制与内容指纹 |
| metadata.py | 使用宿主现有 OneBot 客户端获取机器人身份与群元信息，不发送消息 |
| service.py | 查找、歧义处理、范围绑定、轮流扫描、续查、来源与字符预算 |
| audit.py | 有界且不含聊天正文的审计 |

## 当前实现边界

- 只启用核验过的 4.29.4；内部 runner 或权限代理结构变化时拒绝历史访问。
- 内部接入检查要求找到与当前 context 完全一致的 runner，并识别原始执行器。其他组件若已改造该执行器，本插件保守拒绝查询，不覆盖对方行为。
- 保护范围是此执行器中的新工具准入，不拦截其他插件自己的定时器、直接 API 调用或完全独立的 Agent。
- 工作进程不导入 AstrBot，不在其中初始化宿主数据库，只处理受限协议。
- 资源参数改变后需要重新加载；权限读取会重新解析当前配置，输出前再核对。
- 私聊指纹在工作进程中对大小受限的原始 JSON 计算；不会把完整消息列表解码到主进程，但仍有大小受限的原始文本处理开销。
- 群游标依赖稳定入库 ID。原位正文修改可能在后续页体现；数据库恢复或恶意复用 ID 的场景不能当作固定历史快照。
- 资源紧张导致频率采样不足时，先用 24 小时并告知未知，不能因此自动扩大到 3 天。
- 默认返回条数还受本轮元信息与正文字符限制，长正文会裁剪并标记。调用者可通过记录引用补读，但单条内容仍受长度限制。

## 后续实机验收

本次开发没有访问用户服务器、真实聊天库或外部模型。下一阶段需要在受控环境检查完整 AstrBot 加载/卸载、真实 OneBot 返回格式、配置页面交互及多插件组合。公开发布或生产启用前，应完成这些项目。

外层《实施方案.md》为讨论主稿，本仓库副本同步保存。两轮历史探针保留在外层工作区；本仓库 tests 为实际实现的新测试，不应把旧探针数量当作本版本的用例数量。
