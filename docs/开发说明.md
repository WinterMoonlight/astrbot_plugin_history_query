# 开发与当前实现

## 当前状态

v0.3.0 增加授权私聊对象目录，并将私聊默认读取改为每个来源每轮最多 50 条的最近记录回看。保留三个 LLM 工具、逐用户权限、当前群访问校验、预算队列、只读数据库工作进程、稳定游标和上下文引用。

常规运行使用 Python 标准库以及宿主已经提供的 AstrBot API，不增加额外运行依赖。默认关闭功能，空配置无查询权限。

## 模块

| 文件 | 职责 |
| --- | --- |
| main.py | 工具与管理 API 注册、宿主 hook、版本判断、按事件绑定执行器及卸载 |
| admin.py | 宿主管理员登录上下文校验、配置校验与修订冲突检查、保存、平台元信息 |
| views/settings/ | 由宿主发现的独立设置视图，使用原生 JS/CSS 与 AstrBotPluginView 桥接 |
| .astrbot-plugin/i18n/ | 管理视图中英文标题与说明 |
| config.py / state.py | 严格配置解析、可信事件身份、逐用户授权、受限引用与本轮状态 |
| gate.py | 已验证内部接口的接入；不替换原工具对象，保留宿主权限代理 |
| scheduler.py | 单执行槽位、有限队列、独立累计排队/执行预算 |
| process.py / worker_entry.py | 按需复用和空闲回收独立 Python 进程，超时终止 |
| database.py | 固定只读 SQL、群隔离会话归并、两种正文格式、体积限制与内容指纹 |
| metadata.py | 使用宿主现有 OneBot 客户端获取机器人身份、群元信息及获授权私聊对象昵称，不发送消息 |
| service.py | 查找、歧义处理、范围绑定、轮流扫描、续查、来源与字符预算 |
| audit.py | 有界且不含聊天正文的审计 |

## 当前实现边界

- 只启用核验过的 4.29.4；内部 runner 或权限代理结构变化时拒绝历史访问。
- 内部接入检查要求找到与当前 context 完全一致的 runner，并识别原始执行器。其他组件若已改造该执行器，本插件保守拒绝查询，不覆盖对方行为。
- 保护范围是此执行器中的新工具准入，不拦截其他插件自己的定时器、直接 API 调用或完全独立的 Agent。
- 工作进程不导入 AstrBot，不在其中初始化宿主数据库，只处理受限协议。
- 独立视图保存成功后回收原查询运行状态，后续请求按新配置创建；原配置页修改仍按宿主流程重载。权限读取会重新解析当前配置，输出前再核对。
- 私聊指纹在工作进程中对大小受限的原始 JSON 计算；不会把完整消息列表解码到主进程，但仍有大小受限的原始文本处理开销。
- 群游标依赖稳定入库 ID。原位正文修改可能在后续页体现；数据库恢复或恶意复用 ID 的场景不能当作固定历史快照。
- 资源紧张导致频率采样不足时，先用 24 小时并告知未知，不能因此自动扩大到 3 天。
- 默认返回条数还受本轮元信息与正文字符限制，长正文会裁剪并标记。调用者可通过记录引用补读，但单条内容仍受长度限制。

## 查询结果与确认范围

- 私聊读取器不会伪造昵称，名称由主进程补充。配置或宿主的会话名称优先；没有名称时调用 OneBot `get_stranger_info`，核对返回的用户 ID。仅对已授权且已校验机器人身份的目标调用，每次 0.35 秒并计入本轮执行预算。成功缓存 300 秒、失败缓存 30 秒，最多 256 项，键包含平台实例、机器人 ID 和用户 ID；缓存不参与授权。
- 搜索与补读均返回 `sender_display`、名称来源、`time_display` 和回答规则。AI 私聊历史的 `time` 仍为 null，覆盖范围不伪装成已按日期过滤。当前 QQ 昵称不冒充发送当时的昵称。
- `query_budget.scan_allowance_left` 是共享读取额度；`unread_record_count` 为 null，代表没有统计未读总数。自然语言组织仍由模型完成，合成测试验证数据契约和工具说明，不等于对所有模型输出的保证。
- `find` 支持 `names` 批量定位。开始正文查询前已成功定位的最多 5 个目标构成本轮允许分批读取的来源集合；之后不能追加未定位来源或改变时间边界。每次实际读取仍独立检查当前权限。
- 私聊不再通过 `time_unknown` 阻塞并询问取消日期。日期参数仅对群消息生效；私聊按对话更新时间、ID 及内部记录位置倒序回看，仍将逐条发送时间标为未知。每个私聊每轮最多检查 50 条，跨多次调用及补读累加，同时计入 500 条/5 秒总预算。`continuation` 延续所有来源及各自游标，新一轮可继续向前读。
- `find(list_private=true)` 列出已授权的私聊目录，每页最多 5 个，用 `catalog_cursor` 翻页。数据库按当前授权过滤并固定对话 ID 上界，按会话标识作键集分页；目录只含元信息，不解码聊天正文，不自动选择所有来源去读正文。续查仍核对调用者、平台、机器人绑定与授权。
- 目录的 `conversation_updated_at` 只是整段对话更新时间，不表示最近一条入站消息的时间；目录中也可能存在已经清空的对话。列表不能用作指定日期内发过私聊的确证。

## 管理视图接入

- 使用 4.29.4 的 `views/<name>/index.html` 发现机制、`context.register_web_api` 和 `astrbot.api.web`，不单开 HTTP 服务。前端不持有凭据、不访问父页面 DOM 或 localStorage，不依赖外部 CDN。
- 四个管理 API 只挂载在本插件命名空间，要求宿主提供非空登录用户和匹配的插件名。聊天白名单只控制 LLM 查询，与 WebUI 管理权限分开。
- 页面不提供历史正文浏览或模型测试。启动页只读配置与运行计数；账号识别与群目录由用户点击后通过现有 OneBot 客户端获取，超时 5 秒。
- 配置写入使用宿主 `save_config_async`，必要时回退到后台线程执行 `save_config`，不写历史表。保存前后核对内容修订号；页面内部保存串行化，原配置页仍由宿主独立管理，不宣称跨所有入口的事务隔离。
- 只保存白名单字段，大小限制 256 KiB，并复用 `Settings.parse` 校验。失败保留前端草稿；宿主保存失败时仅恢复仍属于本次写入的内存变更。
- 成功保存会撤销活动引用并关闭旧查询服务；已经读取历史的轮次继续保持工具限制。正在执行的历史查询可能结束或取消，用户可重新发起查询。没有读取历史的普通工具仍按原方式使用。
- 页面无后台轮询。配置页保持打开不会启动数据库工作进程；查询运行时状态在刷新时更新。

本地交互预览通过 `tools/preview_view.py` 提供内存配置与合成平台目录，仅绑定 127.0.0.1，且不进入运行安装包。它调用真实配置编辑逻辑，但模拟宿主桥接，不能证明真实宿主的 iframe、登录态和卸载生命周期已通过验收。

## 后续实机验收

本次 v0.2.0 视图开发没有访问用户服务器、真实聊天库或外部模型。下一阶段需要在受控环境检查宿主视图发现、iframe 桥接、登录态、保存及加载/卸载、真实 OneBot 返回格式与多插件组合。以前版本的部署不等于新视图已经实机验收。

外层《实施方案.md》为讨论主稿，本仓库副本同步保存。两轮历史探针保留在外层工作区；本仓库 tests 为实际实现的新测试，不应把旧探针数量当作本版本的用例数量。
