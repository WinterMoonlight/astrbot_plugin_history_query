# 开发说明

## 当前阶段

已获准进入开发准备。当前提交只包含 Python 包骨架、开发约定和方案，不包含完整插件或历史查询实现。

外层项目根目录的《实施方案.md》是讨论主稿，本仓库 `docs/实施方案.md` 是同步副本。主稿变更后，两处需要同步校对，避免 GitHub 上的方案落后于本地讨论。

## 后续开发顺序

1. 实现并验证低资源调度：单执行槽位、累计排队预算、执行预算、取消与查询进程回收。
2. 实现配置校验、可信调用身份及逐用户会话权限。默认配置不授予跨会话读取权限。
3. 实现版本相关的接入检查和本轮工具准入；失败时拒绝历史读取，保留普通工具原有行为。
4. 实现两类只读读取器、稳定游标、多会话公平调度、上下文补读和来源输出。
5. 接入 AstrBot 入口与配置界面，执行完整宿主的本地合成数据集成测试，再评估发布条件。

队列容量、工作进程内存限制、空闲退出时间及单段 JSON 体积上限尚未最终确定。用测量结果选取保守值，不将探针中的示例数值直接视为生产默认值。

## 计划中的模块职责

| 职责 | 边界 |
| --- | --- |
| 配置、身份与权限 | 只相信宿主事件身份；每个入口独立校验；不让模型选择授权身份 |
| 预算与调度 | 区分累计排队和累计执行时间；限制并发、等待数量和消息扫描量 |
| 版本接入与工具准入 | 只改变本轮的受控入口，不修改全局工具启用状态 |
| 会话目录 | 解析授权名称和别名，处理重名；元信息缓存不得替代成员资格检查 |
| 只读读取器 | 固定参数化查询、只读连接、体积和时间限制；不执行宿主初始化或迁移 |
| 游标与结果 | 绑定调用者和查询范围；说明未完成、删除、超时和未知状态 |
| 审计 | 仅保存必要元信息，不保存聊天正文 |

## 性能约定

- 普通聊天不做额外模型调用、全量检索或工作进程启动。
- 尽量减少数据库返回列、重复 JSON 解析和不必要的数据复制。
- 使用短事务；模型生成和用户等待期间不占用数据库事务或全局查询执行槽位。
- 查询进程按需管理，不因每个小工具调用都无条件创建新进程。
- 不额外引入向量库、服务端搜索引擎、Rust/C++ 组件或完整正文镜像。
- 5 秒是触发停止的执行预算，取消和回收开销需单独测量并如实报告。

## 验证与发布

Python 最低目标版本为 3.12。项目骨架没有额外运行依赖；后续只有确实需要的依赖才加入清单。

当前仅能检查 TOML、Python 包导入及文档结构，不能将其称为插件功能测试。新增调度、权限或读取逻辑时，同步加入有意义的合成数据测试。

外层 `feasibility/` 保存两轮历史实验，隔离环境和实验源码没有复制进本仓库。实验说明中的内部接口方案不等于稳定公共 API，也不能未经验证直接作为生产实现。

发布前至少完成：权限负面对照、宿主无写入验证、超时后台退出、动态数据分页、版本失败时普通功能不受影响，以及完整宿主生命周期测试。需要实际服务器或真实模型联调时，另行明确安排。
